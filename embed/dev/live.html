Live embed harness

This writes real rows. Anything done on this page is recorded against that map exactly as a visitor's session would be, and counts towards its monthly ceiling. Use a map you don't mind adding test data to, and delete the rows afterwards.

/embed/dev.html renders a fixture, which is what makes it useful: no Appwrite, no login, no publish. That also means its map id is not real, so the collector drops every beacon it sends and analytics can never be checked there end to end. This page is the other half — it points the same built bundle at a real published snapshot, so a session recorded here lands in the real tables and shows up on the map's Analytics tab.

Paste the map's live snapshot URL — the data-snapshot value out of the snippet on its Publish page — or pass it as ?snapshot=<url>. The Publish page's Open test page button builds that URL for you.

What to check, with the Network tab open and filtered to collect: search, click a pin, open a card, press Directions — no request appears while you do any of it. Switch to another tab and exactly one POST /api/collect fires, answering 204. Reload the Analytics tab for that map and the session is there. Measurement has to be switched on in the Publish designer and the map republished before any of that happens — the endpoint is baked into the snapshot, so a map published before you turned it on carries no endpoint and correctly sends nothing.

A 204 with no row behind it is the normal answer to every dropped beacon and is deliberately indistinguishable from a stored one: an unpublished map, measurement switched off, a host not on the allowlist, a map over its ceiling. That is the contract in app/api/collect/route.ts — a stranger's page learns nothing from us — so debug it from the server log, never from the status code.
